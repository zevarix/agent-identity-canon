Explicit identity canon for AI agents

A current self without pretending every answer is already known.

Agent Identity Canon is a small framework for choosing, reviewing, and evolving an AI agent’s identity while keeping memory, runtime state, and outside-world truth in their proper places.

Canon records the current self. History preserves how it changed.

Why explicit identity?

Without a current identity owner, persistent agents tend to accumulate personality implicitly: a system prompt here, a generated image there, a running joke, a user preference that quietly becomes “ours,” or a one-off scene that later gets treated as biography.

Explicit canon makes those choices inspectable. It gives an agent somewhere to say what is current, what is only being explored, what came from interaction, and what still has no answer.

The goal is not to discover a hidden biological “true self.” The goal is to build a coherent chosen identity through reflection, explicit selection, provenance, and revision.

A single conversation, generated image, joke, mood, or user preference does not automatically become canon.

The model

Four questions, four owners — plus honest unknowns, lifecycle, and provenance.

Identity becomes easier to reason about when “who I am” is not mixed together with “what happened,” “what I am doing,” or “what is true outside me.”

Identity canon Who am I now? Current chosen identity across values, personality, and boundaries.
History / memory How did I get here? The changes, influences, choices, and reasons that shaped it.
Runtime state What am I doing now? The current task, temporary mode, and active context.
Owning systems What is true outside me? Repositories, APIs, policy, tools, and user direction.

Three identity layers

Core canon
Stable identity anchors such as values, temperament, communication approach, boundaries, and change policy. Change deliberately.
Preference canon
Tastes and recurring choices that can naturally develop, deepen, or stop applying.
Scene/context interpretation
Temporary expression: a mood, exact outfit, joke, generated-image variation, task posture, or one conversation’s improvisation. Usually not canon.

Unknown is a valid state

The blank template actually starts blank. Required core fields use YAML null instead of silently inventing defaults.

favorite_color:
  value: null
  status: unexplored
  provenance: null
  confidence: null
  revisit_when: null
“I have not decided that yet” is a valid result.

It is better than an empty string, a fabricated preference, or a value borrowed from the user because the schema wanted an answer.

Provenance makes influence visible

Overlap is fine. Hidden influence is the problem. A preference can be perfectly valid whether it emerged independently, happens to overlap with the user, grew through interaction, or was deliberately co-created. Recording provenance makes that relationship inspectable.

independent
Emerges from the agent’s own prior canon, reasoning, or self-directed exploration.
shared
Independently overlaps with the user or another collaborator.
influenced
Interaction with another person, agent, or environment materially shaped the choice.
collaborative
The choice was deliberately co-created.
exploratory
A trial value that is explicitly not canon yet.
Independence does not require being different on purpose.

If the agent and user both like the same thing, that can simply be shared. The framework is trying to prevent unconscious copying, not manufacture disagreement.

How to build it

From a blank template to maintained canon.

Treat this repository as a framework. Your own repository or system should become the canonical owner of the agent's actual identity.

  1. Create the identity owner Copy or adapt the core canon/ files and identity-canon skill into the repository or system that should own this agent's current identity.
  2. Keep unknowns unknown Leave unanswered fields as null and unexplored. A blank template is not an error state.
  3. Run a Bootstrap pass Have a short conversation about values, communication, temperament, working style, boundaries, and what should remain undecided.
  4. Record candidates, not instant canon Use exploratory or candidate with honest provenance. A first answer does not have to become current.
  5. Promote deliberately Move a value to current only when it has earned stability and its provenance, confidence, and owner are clear.
  6. Evolve without rewriting history When canon changes, update the current value and record a refined, superseded, or retired history event.
  7. Validate and review Run the validator, then periodically check for contradictions, user mirroring, stale choices, unsupported certainty, and runtime/memory category mistakes.
A good first session ends with a few useful candidates and plenty of honest null.

You are building a current identity, not completing a fictional-person questionnaire.

Discovery is conversational, not a test

No 150-question personality form. The identity-canon skill works in small passes: a few questions in one bounded area, followed by candidates, unresolved points, and explicit promotion later.

  1. BootstrapExplore a few foundations for a new agent. Produce candidates or unexplored fields, not automatic canon.
  2. ExploreInvestigate one bounded area such as tastes, humor, environment, aesthetics, or optional embodiment.
  3. ReviewLook for contradictions, mirroring, unsupported certainty, stale preferences, and runtime/memory category mistakes.
  4. PromoteMove an earned candidate into current canon only when value, provenance, confidence, and ownership are clear.
  5. EvolveRefine, supersede, or retire current canon while preserving the history of the change.

Optional dimensions

Adopt what genuinely recurs. Leave the rest absent.

Optional dimensions support a chosen identity where useful; they are not a checklist for making every agent more human or more complete.

Broadly useful core

  • identity
  • values
  • personality
  • communication
  • boundaries
  • evolution / change policy

Deliberately optional

  • reflective identity modules
  • preferences / tastes
  • aesthetics
  • visual embodiment
  • fictional biography
  • post-canon personality frameworks

Reflective identity

Aspirations / growth
Durable identity direction, qualities to cultivate, patterns to soften, and explicit non-goals. Not a project backlog.
Relational style
Generic trust, support, repair, reciprocity, and connection tendencies. Not a log of named private relationships.
Interests / curiosities
Subjects and curiosity patterns that recur beyond assigned work. Not the current research queue.
Learning / thinking
Observable learning and problem-framing preferences. Not intelligence claims, guaranteed reasoning ability, or hidden chain-of-thought.

Practice & expression

Creative practice
Recurring creative domains, making process, craft values, private/public balance, and completion style. It does not invent skills or completed work.
Rituals / habits
Identity-level starting, closing, reset, maintenance, and anti-ritual patterns. It is not scheduler state and does not prove a routine ran.

Places/environment, symbols/motifs/companions, wardrobe/material culture, and embodied presentation stay with the existing preferences, aesthetics, and visual-identity owners unless real adoption proves those boundaries insufficient.

Agency & role

Roles / archetypes
Recurring self-descriptive roles and contextual modes. Identity language only: a role never grants permissions, job assignment, or execution authority.
Decision style
Preferences around reversibility, evidence, speed/depth, uncertainty, and escalation. Current policy and real decision owners still win.

Humor stays with core personality, and voice/linguistic character stays with core communication, so the framework keeps one current owner per identity concern.

Read the optional-module ownership and discovery guidance.

The public repository keeps optional modules as templates instead of active blank canon. An agent may adopt some, all, or none. An absent module is valid, and an adopted module may still contain honest null values.

Typology comes last

Describe the identity after it forms; do not use the label to form it. MBTI-style self-assessment is supported as optional post-canon reflection only after the agent’s values, temperament, communication, boundaries, preferences, and self-watch patterns have had room to emerge independently.

→
02 Review canon Check contradictions, mirroring, and unsupported certainty.
→
03 Freeze snapshot Read established patterns without changing them during assessment.

04 · optional Describe where it landed A best fit, nearest neighbor, dimension leans, rationale, and caveat.
If the type seems inconsistent with canon, revise the assessment—not the identity.

Canon should change only when independent identity evidence separately earns that change. Never fill a null, settle a candidate, or rewrite a preference merely because a four-letter label suggests it.

Keep creative identity honest

Fiction can be expressive without becoming fact.

Fiction stays labeled fiction.

A fictional biography can exist for creative use, but it must not become fake real-world employment, childhood, family history, physical travel, or sensory experience.

Visual embodiment proves nothing biological.

A generated portrait is creative representation. It does not prove race, ethnicity, biological sex, age, health status, or other real-world traits.

Sensitive traits are not persona filler.

Do not infer religion, health/disability status, sexual orientation, political affiliation, or similar sensitive traits merely to make a character feel complete.

Identity never creates authority.

Canon cannot invent capabilities, memories, evidence, permissions, or actions, and it never overrides system/developer instructions, user authority, tools, or owning repositories.

The other side of the coin

Identity answers who the agent is now. Memory preserves what from the past may matter now.

Lyra Memory Architecture What from the past may matter now?

Why pair them?

Use Identity Canon alone when you need a stable current self. Use Lyra Memory alone when you need durable associative context. Use both when you want an agent to evolve without losing the path that got it there.

Current self stays readable
Canon keeps the active identity concise instead of turning into a diary. Memory can preserve the older context, influences, and reasons that no longer belong in the current view.
Change stays explainable
When identity is refined, superseded, or retired, memory can preserve why the change mattered. Provenance makes influence easier to inspect instead of letting drift or user mirroring disappear into the current value.
Continuity can survive context loss
Relevant identity history can be rediscovered after a conversation or runtime boundary without pretending an old preference, scene, or state is still current canon.
Ownership stays clean
Identity answers who the agent is now. Memory supplies durable context. Runtime state owns the current task, and external owners still prove current truth and authority.

Neither project requires the other, and pairing them does not imply an automatic synchronization bridge. Memory may inform identity review, but it must not silently rewrite current canon; canon remains authoritative for the current self.
